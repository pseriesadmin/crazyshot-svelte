## 8. 외국인증명 최초등록/재등록도 "버튼 없는 자동 등록"으로 완전 통합 (핵심 재설계)

**발단**: Stephen 리포트 — 외국인증명 최초등록 화면(체류기간 선택 + 4슬롯)에 파일 1개를
선택해도 자동 등록이 안 됨. 원인: 3번 항목에서 "콤보 4개 전부 채워야 자동제출" 제약을
안 없앤 채로 남겨뒀던 것.

**수정**: 이 제약 자체를 폐기 — 최초등록/재등록 폼을 병합(merge) 자동제출 패턴으로 완전
통합. 이제 불필요해진 배치제출 함수(`uploadForeignDoc`) + 로컬 스테이징 상태 12개 식별자
전부 삭제. `requestForeignReRegister()` 확인토스트도 제거(더는 "전체 삭제"가 아니므로
문구가 사실과 안 맞음).

**⚠️ 이 재설계가 겉으로 드러낸 숨은 결함들** — "4개를 한 번에 낸다"는 전제 위에 조용히
얹혀있던 안전장치들이 명시적으로 다시 필요해짐:

## 9. Migration #495 상세 (Stage+Production 적용 완료)

`update_user_doc_url` RPC의 foreign 분기: `foreign_verified_at = NOW()` (무조건) →
`CASE WHEN array_length(p_doc_url,1) >= 4 THEN NOW() ELSE NULL END`. identity 분기는
무변경(identity는 애초에 "콤보 완성" 개념이 없어 해당 없음 — §22-5 "5종 전부 필수 아님").
부수효과: 완성된 콤보에서 개별삭제로 4→3이 되면 `foreign_verified_at`이 자동으로 NULL
복귀 — "완료" 배지가 항상 실제 등록 상태와 일치.
파일: `supabase/migrations/20260914030000_495_foreign_verified_at_combo_complete_only.sql`
실측 검증(Stage 직접 SQL 조회): 2/4 등록 시점 `NULL` 확인 → 4/4 완성 시점 정확히 타임스탬프
기록 확인.

### 신규 세션 참고 시 유의사항

- 이 세션이 만든 마이그레이션(#495)은 Stage+Production 양쪽 적용 완료 — 추가 조치 불필요.
- 본인증명·외국인증명 등록 UX는 이제 **완전히 동일한 패턴**(버튼 없음, 슬롯 선택 즉시
  개별 자동 병합 제출)으로 통일됨 — 향후 이 영역을 다시 만질 때 "본인증명은 되는데
  외국인증명은 안 된다"는 류의 비대칭 버그가 재발하지 않도록, 새 기능은 반드시 양쪽에
  동시 적용할 것.
- `foreign_verified_at`(외국인증명 인증완료 여부)의 유일한 정본 판정 기준은 **"현재 콤보
  기준 4종 전부 등록됐는가"**이며, RPC(`update_user_doc_url`)가 이를 자동으로 계산해
  기록/해제한다 — 새로운 코드에서 이 컬럼을 직접 세팅하는 경로를 추가하지 말 것(11번
  항목의 `/api/cms/upload-doc` 결함이 정확히 이 실수의 재발 사례).
- `.claude/harness/TASK.md` 최상단에는 이 시각 기준 **다른 병렬 세션들의 항목**(CMS
  예약변경/취소 CRITICAL 작업, front UI 전역 정밀검증 등)이 더 섞여 있음 — 신규 세션이
  "이 세션" 라벨만 보고 전부 자기 작업으로 오인하지 않도록 주의 필요(이 프로젝트의 알려진
  다중세션 오염 이슈).
- 미해결 후속 태스크 1건: `task_d37d0806`(CMS `/api/cms/upload-doc` verified_at 결함) —
  아직 아무도 착수하지 않음.
