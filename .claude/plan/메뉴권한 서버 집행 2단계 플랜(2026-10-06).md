## 3. Stephen께 필요한 결정 (질문)

- **Q0(미해결, 1e에서 넘어온 건)**: `api/cms/customers/[id]/coupons`·`summary`는 현재 **"상담 또는 고객목록" any-of**로 구현됨. 원래 제안은 "상담 단독". 호출처는 상담 고객패널뿐이라 any-of는 "고객목록 권한만 있어도 상담 패널 데이터를 읽는" 우회가 남음. → 상담 단독으로 좁힐까요? (좁히면 고객목록 ON·상담 OFF 계정은 상담 패널 데이터를 못 봄 = 정책상 맞음)
- Q1: 계약서 양식 읽기(A1)는 `rental.reservation` 또는 `consulting.chat` 중 하나면 허용(권장)으로 둘까요?
- Q2: 푸시 필터(B1)를 결제·예약·서명→예약대여현황, 서류→고객목록으로 확대할까요? (권장: 예. 단 조회 실패 시 전원 발송 유지)
- Q3: 업로드(A3)는 "고객 첨부(`log/`)는 무게이트, 그 외 경로(상품 이미지 등)만 메뉴 권한" 분기로 갈까요?
- Q4: 화면 진입(레이아웃)도 조회 실패 시 차단으로 맞출까요, 아니면 "화면은 열리고 API만 막힘"을 정책으로 문서화만 할까요? (권장: 문서화, 로그인 전면 장애 방지)
- Q5: `/cms/set/signature`·`/cms/accounts/*`는 새 메뉴 키를 만들어 계정별 권한에 포함할까요, 현행(매니저 이상 역할 게이트)을 유지할까요?
- Q6: 프론트 크레이지로그 글 관리도 `promotion.content` OFF 계정은 막을까요?
- Q7: 1b~1h 커밋 전에 2-A를 먼저 끝낼지, 1단계를 먼저 커밋·배포하고 2단계를 그 위에 쌓을지? (권장: **1단계 먼저 커밋·배포**, 배포는 DB 변경 없음 → 코드 배포만)

## 4. 위험·주의

- 1단계는 **코드 배포만으로 효력**(DB 변경 없음). Production에는 현재 차단 설정 계정이 없어 배포 직후 영향 0. 다만 배포 후 첫 차단 설정 시점에는 Stage 실계정 검증과 같은 시나리오로 Production을 읽기 전용 점검 권장.
- 2-C의 `upload`는 고객 크레이지로그 첨부와 같은 엔드포인트라 **분기 오류 = 고객 기능 장애**. 고객 세션 회귀 고정 테스트를 먼저 작성.
- 2-F는 DB 정책 변경이라 코드 롤백만으로 되돌릴 수 없음 → 롤백 SQL 선작성 필수.
- 작업 트리에 다른 세션 변경 다수 — 2단계 커밋도 이 세션 파일만 선별.
