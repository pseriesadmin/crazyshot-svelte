### 근본 원인 (복수)

1. **세션 시작 점검 절차 미준수 (1차 원인)**
   CLAUDE.md는 "세션 시작 시 반드시 확인: 1) TASK.md 2) GSD_LOG.md 3) AGENTS.md
   4) HANDOFF.md 5) learnings/*.md"를 명시하고 있으나, 본 세션은 첫 요청(부모 상품
   ProductDetailPanel 점검)에 바로 `git diff`로 코드 상태만 확인하고 하네스 문서
   점검을 생략함. 이 점검을 정상 수행했다면 "코드에는 대규모 rep-section 변경이
   있는데 TASK.md에 대응 항목이 없다"는 불일치를 세션 초반에 바로 포착했을 것.

2. **작업 범위를 "이번 세션에 지시받은 것"으로만 좁게 해석 (2차 원인)**
   이후 하네스 기록을 남길 때도 "Stephen이 이번 세션에 요청한 항목"만 기록 대상으로
   삼고, 세션 시작 시점에 이미 작업트리에 존재하던 미기록 diff를 별도로 감사하거나
   backfill하려는 시도를 하지 않음. TASK.md 갱신을 "내가 한 일의 로그"로만 취급하고
   "현재 작업트리 상태의 완전한 문서화"로 취급하지 않은 인식 오류.

3. **선행 세션의 HANDOFF 미갱신 (근본 원인 — 상위 세션 책임)**
   `HANDOFF.md` 최종 갱신일이 2026-07-20으로, rep-section 작업이 이뤄진 것으로
   추정되는 기간(2026-07-25 이후)의 세션 인수인계 기록이 전혀 없음. 해당 작업을
   수행한 세션(들)이 종료 시점에 TASK.md NOW 블록 생성/완료 처리 및 HANDOFF.md
   갱신이라는 하네스 필수 절차를 건너뛴 것이 근본 원인.

## 4. 재발 방지 원칙 (확정)

1. **커밋 제안 전 필수 교차검증**: 커밋 대상 파일을 확정하기 전, 반드시
   `git diff --stat <파일>`로 실제 변경 규모를 확인하고, TASK.md에 그 규모에
   상응하는 항목이 존재하는지 대조한다. diff가 크고(대략 수십~수백 라인 이상)
   대응 TASK 항목이 없다면 커밋 메시지 작성 전에 먼저 사후 기록부터 보완한다.
2. **세션 시작 점검은 "코드 확인"보다 먼저**: 어떤 요청이든(단순 점검 요청 포함)
   `git status`로 dirty 파일을 먼저 훑고, 그 중 TASK.md 최근 NOW 블록에 대응
   항목이 없는 파일이 있으면 즉시 Stephen에게 "이 파일은 미기록 변경분인데
   확인이 필요하다"고 알린다 — 코드 리뷰를 시작하기 전에.
3. **하네스 기록은 "내 작업 로그"가 아니라 "현재 diff의 완전한 문서"**: 세션
   중 TASK.md/GSD_LOG.md를 갱신할 때, "이번에 요청받아 내가 만든 변경"만이 아니라
   "지금 커밋하려는 파일 전체의 diff"를 기준으로 누락 여부를 판단한다.
