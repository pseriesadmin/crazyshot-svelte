# harness-orchestrate — 메인 Claude 지휘 절차 (v1.0, 2026-10-27)

> 에이전트는 서로를 부를 수 없다(Agent 도구는 메인만 사용). 이 스킬은 **메인**이 따른다. 합격·반려 종합은 sp3, GATE 승인은 Stephen.
> 원칙: 필요한 에이전트만, 한 번에 병렬로. 단순 문구·레이아웃 수정은 sp3 하나(또는 생략)로 끝낸다 — 토큰 절약.

## 1. 입력 수집 (명령 3개)
```
git status --short ; git diff --stat        # 이번 세션 변경 파일 (세션 범위 밖 파일은 제외하고 사용자에게 알린다)
GSD_LOG.md 마지막 🧾SESSION 행            # 세션 파일 목록 기준
```
변경 파일이 이번 세션 것인지 불분명하면 목록을 보여주고 대상을 확인받는다(범위 외 검수 금지).

## 2. 위험 등급 → 기본 구성
| 등급 | 해당 | 기본 호출 |
|---|---|---|
| ROUTINE | UI 스타일·문구·기존 컴포넌트 수정 | sp3 (경량) 또는 생략 후 결과 보고 |
| BOUNDARY | 단일 서비스 로직·신규 컴포넌트 | sp3 |
| CRITICAL | 결제·예약·권한·계약·개인정보·다중 파일·DB | sp3 + 아래 신호별 추가 |

## 3. 신호 → 추가 에이전트 (해당하는 것만)
| 신호(변경 내용) | 추가 호출 |
|---|---|
| `supabase/migrations/**`, RPC·RLS·GRANT, 신규 테이블 | **sp6-db-migration** |
| 요금·쿠폰·적립 산식, 알림(채팅카드·push.ts·sms.ts), 상태 전이 표, 종료상태, 권한 게이트·메뉴 매핑, 배송지역, 서류 조합, 계약서 치환 (sp7 동기화 표 영역) | **sp7-sync-guard** |
| 인증·세션·OTP·웹훅·결제 승인·파일 업로드·외부 입력→DB/URL·시크릿·크레이지챗 AI 입력 | **sp5-security-agent** (범위 한정 A-Lite) — 보통 sp3의 SP5_REQUEST 후 호출 |
| `.claude/rules/**`, `rules-ref/**`, `CLAUDE.md`, `.claude/agents/**` 수정 | **sp10-rules-curator** (대상 지정) |
| 위 신호 없음 | sp3만 |

**모든 등급 공통(2026-10-30)**: 커밋 후 `node scripts/verify-clean-checkout.mjs HEAD`(또는 배포 후 `origin/main`)로 "커밋된 상태 그대로 정의 누락 0"을 확인한다. 여러 세션이 같은 파일을 건드렸다면 sp3 호출 프롬프트에 그 파일 목록과 `git diff HEAD -- <파일>` 확인을 명시한다. 이 검사 미실행은 "미검증"이며 GATE E 통과로 취급하지 않는다.

판단이 애매하면 호출하지 말고 "붙이지 않은 이유"를 한 줄로 보고(사용자가 요청하면 추가 호출).
TDD 도메인(결제·예약·보안 등)은 구현 단계에서 harness-executor가 sp2 호출 요청서를 출력하므로 그 요청서에 따라 메인이 sp2를 호출한다.

## 4. 호출 방법
- 독립적인 에이전트는 **한 메시지에서 병렬** 호출한다(Agent 도구 여러 개 동시).
- 프롬프트에 반드시 포함: 프로젝트 루트, **대상 파일 목록(세션 범위)**, 변경 요지, 등급, 읽기 전용·git 금지, 보고 형식(비개발자 요약 먼저).
- sp6은 Stage/Production project_id를 명시해 조회하도록 지시. sp7은 변경이 속한 동기화 표 행을 알려준다.
- 이미 같은 지문(fp)으로 통과한 sp5 결과가 GSD_LOG에 있으면 REUSE(재호출 생략): `node scripts/harness-scan.mjs --fingerprint --files …`

## 5. 종합 (메인이 작성)
```
┌ 오케스트레이션 결과 ─────────────────────
│ 등급: {ROUTINE|BOUNDARY|CRITICAL}   호출: {sp3, sp6, …}   생략: {에이전트: 이유}
│ BLOCKER n · MAJOR n · MINOR n · 미검증 n   (에이전트별 1줄)
│ 판정: GATE E 통과 가능 / 반려(사유) / 보류(미검증 해소 필요)
└──────────────────────────────────────────
```
- 한 에이전트라도 BLOCKER → 반려. 미검증 항목은 통과로 취급하지 않는다.
- 에이전트 간 결과가 충돌하면 근거(파일:줄)가 더 강한 쪽을 택하되 사용자에게 충돌 사실을 보고.
- 사용자 보고는 비개발자 언어: "어떤 상황 → 무엇이 문제 → 왜 중요 → 다음 조치".
- GSD_LOG에 `🧾SESSION`(파일·fp) 및 에이전트별 결과 1줄(예: `🗄️SP6`, `🔁SP7`, `🛡️SP5`)을 기록한다.

## 6. 하지 않는 것
```
· 사용자 승인 없는 git 쓰기, 배포, DB 적용 (모두 Stephen) · 에이전트 결과를 임의로 수정해 통과 처리
· 세션 범위 밖 파일 검수 · 자동 수정 에이전트 호출 · 신호 없는데 전원 호출(토큰 낭비)
```
정기: sp5 위협 인텔 주 1회, sp10 월 1회, 배포 후 운영 점검은 sp4 체크리스트.
